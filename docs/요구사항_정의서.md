# 요구사항 정의서

이후 기능은 이 ID로만 말한다. 충족 여부는 웹앱 테스트 문서의 P/F에 그대로 옮긴다.

| ID | 요구사항 | 담당 | 1차 충족 |
|---|---|---|---|
| REQ-01 | 프로필 저장. 같은 이메일이면 그 행을 갱신한다. 조회는 `GET /users/{id}` | `users.py` | P |
| REQ-02 | 공고 목록은 지역·공급유형·페이지로 거른다. 단건 조회가 있다 | `listings.py` | P |
| REQ-03 | 희망 지역 공고를 자격·구간으로 정렬해 최대 50건. 없는 사용자는 빈 목록 | `recommendations.py` | P |
| REQ-04 | 자격은 가능/불가능. 확률은 상/중/하. "당첨 확률"이라고 쓰지 않는다 | `eligibility_filter.py`, `probability_estimator.py`, `cutoff_model.py` | P (가점은 국토부 가점표. 만 30세 미만 미혼 0점 규칙은 생년월일을 입력한 경우만 적용. 기준 커트라인은 회귀 모델·없으면 3년 평균) |
| REQ-05 | 공고 종류(분양·임대)에 맞는 대출 후보 최대 20개. 한도 문장으로 예상 한도를 계산해 부족 자금을 못 채우는 상품은 뺀다. 한도를 모르면 후보에 남기되 뒤에 둔다 | `loan_matcher.py` | P (규제지역·소득(은행 DSR 40%, 입력한 경우만) 반영. 정책대출은 디딤돌만 반영(소득·주택가격·면적 조건 판단, 기준 2026-10, 공식 안내 hf.go.kr). 버팀목 등은 공식 확인 전이라 미반영) |
| REQ-06 | 계약금은 공고문에 적힌 숫자(총액 또는 비율)만 쓴다. 10%로 가정하지 않는다. 숫자가 없으면 "추후공지", "공고에 비율 없음", "공고 확인 전"으로 나눠 표시한다. 프론트는 비율을 곱하지 않는다 | `listing_view.py`, `notice_parser.py` | P |
| REQ-07 | 열어 둔 공고의 문장만 보고 답한다. 근거가 없으면 모른다고 한다 | `chat_graph.py`, `listing_rag.py`, `vector_store.py`, `embedder.py`, `notice_chunker.py`, `llm_client.py`, `chat.py` | P (공고문 원문을 조각내 벡터 DB(Chroma)에 색인, 의미 검색(mpnet)+글자 TF-IDF 하이브리드. 원문이 없는 공고는 필드 검색. LLM은 로컬 Ollama(exaone3.5) 또는 OpenAI. 답에 근거 번호 [n]을 붙인다. 평가: `backend/scripts/eval_rag.py`, `backend/scripts/eval_llm_answers.py`, `docs/LLM_답변_평가_결과서.md`) |
| REQ-08 | 자격·가점·대출 금액은 LLM이 계산하지 않고 추천·대출 API를 안내한다 | `chat_graph.py`(api_agent), `intent_classifier.py` | P (챗은 LangGraph 그래프로 구성. `docs/챗_그래프_구조.md`) |

범위 밖: 로그인, 사용자 목록, 서류 자동 작성, 잡담 챗봇, GitHub `main` 직접 push.
