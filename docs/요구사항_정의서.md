# 요구사항 정의서

이후 기능은 이 ID로만 말한다. 충족 여부는 웹앱 테스트 문서의 P/F에 그대로 옮긴다.

| ID | 요구사항 | 담당 | 1차 충족 |
|---|---|---|---|
| REQ-01 | 프로필 저장. 같은 이메일이면 그 행을 갱신한다. 조회는 `GET /users/{id}` | `users.py` | P |
| REQ-02 | 공고 목록은 지역·공급유형·페이지로 거른다. 단건 조회가 있다 | `listings.py` | P |
| REQ-03 | 희망 지역 공고를 자격·구간으로 정렬해 최대 50건. 없는 사용자는 빈 목록 | `recommendations.py` | P |
| REQ-04 | 자격은 가능/불가능. 확률은 상/중/하. "당첨 확률"이라고 쓰지 않는다 | `eligibility_filter.py`, `probability_estimator.py`, `cutoff_model.py` | P (가점은 국토부 가점표, 기준 커트라인은 회귀 모델·없으면 3년 평균) |
| REQ-05 | 부족 자금과 한도가 비었거나 이상인 대출 후보 최대 20개 | `loan_matcher.py` | P (소득·지역 미반영) |
| REQ-06 | 계약금은 분양가 10% 가정. 화면에 가정치라고 표시. 프론트는 0.1을 곱하지 않는다 | `listing_view.py` | P |
| REQ-07 | 열어 둔 공고 문장만 보고 답한다. 근거가 없으면 모른다고 한다 | `listing_rag.py`, `chat.py` | P (검색은 TF-IDF, KURE는 선택) |
| REQ-08 | 자격·가점·대출 금액은 LLM이 계산하지 않고 추천·대출 API를 안내한다 | `intent_classifier.py` | P |

범위 밖: 로그인, 사용자 목록, 서류 자동 작성, 잡담 챗봇, GitHub `main` 직접 push.
