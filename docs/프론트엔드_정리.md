## 1. 프론트엔드가 지켜야 할 원칙

> 출처: `260917_3_주제_방향성_정리.md` 11장

1. **계산 로직을 프론트엔드에 넣지 않는다.**
   계약금 10% 역산, 대출 한도 계산, 자격 판정 같은 로직은 전부
   `backend/app/services/`에 두고, 프론트는 **결과만 받아서 표시**합니다.
   - 예: 계약금은 `contract_deposit` 값을 그대로 쓰고, 분양가에 0.1을 곱하지 않습니다.
   - `deposit_is_estimate`가 `true`이면 "공고 기준 가정치"라고 표시합니다. (요구사항 REQ-06)
2. **API 응답을 화면에 바로 쓸 수 있는 형태로 받는다.**
   - ❌ 프론트에서 `분양가 * 0.1` 계산
   - ✅ 백엔드가 `contract_deposit: 20000000`을 바로 내려줌
3. **모바일 우선으로 화면을 그린다.** (STEP 7, 9-2장)
4. 프론트가 단순할수록 이후 PWA·웹뷰·Flutter 등 다른 형태로 옮기기 쉽습니다.

## 2. 화면 구성 (라우트)

`frontend/src/App.js` 기준, 접근 권한으로 두 그룹으로 나뉩니다.

| 그룹 | 경로 | 페이지 | 설명 |
|---|---|---|---|
| 누구나 | `/` | HomePage | 배너, 빠른 메뉴, 접수중/예정/마감 탭 |
| 누구나 | `/listings` | ListingsPage | 전체 공고 목록. 지역·공급유형·검색어로 거름 |
| 누구나 | `/listings/:id` | ListingDetailPage | 공고 1건 상세 |
| 내 정보 필요 | `/start` | InputFormPage | 온보딩(3단계 입력 폼) |
| 내 정보 필요 | `/dashboard` | DashboardPage | 맞춤 추천 결과 |
| 내 정보 필요 | `/loans` | LoanSimulatorPage | 대출 매칭·자금 계획 |
| 내 정보 필요 | `/chat` | ChatPage | 공고 질문(챗봇) |
| 내 정보 필요 | `/commute` | CommutePage | 통근 시간 계산 |

> 로그인/회원 인증은 요구사항 범위 밖입니다(`요구사항_정의서.md`). 사용자 식별은
> 온보딩에서 만든 `user_id`를 Redux 스토어에 들고 다니는 방식입니다.

## 3. 온보딩 (`/start`, `InputFormPage.jsx`)

- 기획안 "PC 시안 01: 좌우 분할형 온보딩" 구조를 따릅니다.
- 3단계: **기본 정보 → 청약 자격 → 자금·지역**
- 마지막 단계에서 `POST /users/`로 저장 후 `/dashboard`로 이동합니다.

## 4. 공고 질문 챗봇 (`/chat`, `ChatPage.jsx`)

- 기획안 "PC 시안 05: 3단(관심 공고·대화·근거) 공고 질문 화면" 구조입니다.
- `listingId`가 있으면 그 공고 문장 안에서만 답을 찾고, 근거 문장을 같이 보여줍니다.
- 자격·가점·대출 금액은 챗봇이 계산하지 않고 추천·대출 API로 안내합니다(REQ-08).

## 5. 상태 관리 / 공용 모듈

| 파일 | 역할 |
|---|---|
| `src/api/client.js` | 백엔드 호출 함수 모음 (axios 인스턴스 하나) |
| `src/store/userSlice.js` | 온보딩 입력값, 저장된 `user_id` |
| `src/store/listingsSlice.js` | 공고 목록/추천 결과 |
| `src/store/loansSlice.js` | 대출 매칭 결과 |
| `src/constants/regions.js` | 지역 코드 ↔ 지역명 매핑 |
| `src/utils/format.js` | 금액(원화), 날짜, D-day, 접수 상태 표시 포맷 |
