# 커뮤니티 시연 데이터

커뮤니티는 최종 시연까지 **가짜 데이터만 사용하는 브라우저 전용 기능**이다.
실제 공고·청약진단 데이터나 기존 커뮤니티 API/DB와 연결하지 않는다.
서비스의 로그인 상태는 접근 검사에만 사용하고, 서버 사용자 ID를 별도의 계정 범위로 변환한다.
진단·소득·자산·주소 등의 사용자 객체는 커뮤니티에 전달하지 않는다.

## 로그인과 계정별 접근

- 비로그인 방문자(진단 때문에 임시 사용자 ID만 생긴 손님 포함)는 커뮤니티에 들어갈 수 없다. 로그인 안내창과 로그인 버튼을 표시하며 시연 iframe을 생성하지 않는다.
- 현재 시연 데이터는 **이메일 `saessak@example.com` + 닉네임 `새싹`**으로 서비스에 로그인한 계정에만 제공한다. 닉네임만 새싹인 다른 이메일의 계정에는 제공하지 않는다.
- 안내창의 로그인 버튼은 기존 서비스 로그인 창에 위 정보를 미리 채운다. 기존 계정은 로그인, 처음 사용하는 계정은 기존 ‘결과 저장하고 시작’으로 등록한다. 서비스 로그인 자체는 기존 사용자 API를 사용한다.
- 다른 로그인 계정에는 ‘새싹 시연 계정 전용’ 안내만 표시한다. 향후 다른 계정의 커뮤니티를 열 때는 해당 계정의 빈 상태/전용 데이터로 시작하도록 저장 계층을 준비했다.
- 게시판, 글 상세, 친구, 메시지 등 직접 URL 진입도 같은 검사를 거친다. 시연 HTML 파일을 단독으로 열어도 로그인 안내만 표시한다.
- 로그아웃·계정 전환 시 기존 iframe을 제거한다. 다른 탭에서 로그아웃해도 로그인 저장 변경을 감지해 제거한다. 남아 있는 화면의 이벤트와 비동기 첨부 미리보기도 현재 계정을 재확인한다.
- 서비스 홈에서도 비로그인/다른 계정에는 시연 게시글 대신 로그인 안내를 표시한다.
- 이 검사는 현재 서비스의 브라우저 `member` 상태에 기반한 **시연 UI/데이터 분리**다. 비밀번호나 서버 세션에 의한 운영용 인증·인가를 새로 구현한 것은 아니며, 클라이언트에 포함된 가짜 원본 파일 자체를 비밀로 만드는 기능도 아니다.

## 파일과 경계

`frontend/public/prototype/community-demo/`에 독립 화면·스타일·데이터를 둔다.

| 파일 | 역할 |
| --- | --- |
| `seed.js` | 가짜 프로필, 29개 게시글, 댓글, 친구 요청, 대화의 초기 데이터 생성 |
| `session.js` | 로그인 계정 검사, 새싹 시연 계정 판별, 최소 계정 범위 전달 |
| `storage.js` | 시연 전용 저장 키와 데이터 출처·버전 검사 |
| `attachments.js` | 시연 전용 IndexedDB의 파일 원본 저장·다운로드 |
| `recommendations.js` | 시연 프로필·공개 작성글의 로컬 코사인 유사도 추천 |
| `management.js` | 페이지 구분, 대화 숨김·복원, 내 활동 선택 정리 |
| `app.js`, `styles.css`, `index.html` | 승인한 커뮤니티 시안과 브라우저 안에서의 상호작용 |
| `host.js`, `host.css` | 공통 서비스 헤더·본문 영역과 화면 이동 연결 |

## 공통 디자인

서비스의 실제 `header('community')`를 그대로 표시한다. 커뮤니티 안에서 별도 서비스 헤더를 만들거나 공통 헤더·로그인 UI를 숨기지 않는다.
시연용 닉네임·메시지·내 정보는 커뮤니티 하위 메뉴에 배치해 실제 로그인 정보와 구분한다.
`frontend/public/prototype/design-system.css`의 색상·폰트·기본 버튼 스타일을 서비스와 커뮤니티가 함께 사용한다.
본문의 게시판·친구·메시지 배치는 유지하며, 전용 iframe은 데이터/스타일 충돌을 막는 본문 경계로만 사용한다.
공통 헤더의 높이를 관찰해 본문 높이를 맞추므로 커뮤니티에서 서비스 헤더가 잘리거나 이중으로 나오지 않는다.
디자인을 공유하더라도 전체 로그인·진단 데이터는 시연 프로필로 전달하지 않는다. 계정 범위, 닉네임, 시연 계정 여부만 전달한다.

게시글 ID는 `demo-post-*`, 직접 작성한 글은 `demo-local-post-*`이다.
초기 게시글에는 `example: true`, 저장 데이터에는 `dataSource: "community-demo"`를 붙인다.
가짜 유저의 숫자 ID는 이 폴더 안에서만 쓰는 식별자이며 서버의 `user_id`와 관계없다.
초기 데이터와 사용자 입력은 객체를 공유하지 않으며, 초기화할 때 새 데이터 객체를 만든다.

## 저장 정책

- 활성 저장 키: `cheongyak:community-demo:v2:account:user-<서버 사용자 ID>`
- 저장 데이터의 `ownerId`와 시연 데이터 종류(`fixtureSet`)를 검사한다. 다른 계정의 데이터를 키만 바꿔 복사해도 가져오지 않는다. 가짜 작성자 ID `0`은 각 계정 범위 내부에서만 사용한다.
- 과거 공용 키 `cheongyak:community-demo:v1:standalone`과 공용 첨부 DB는 소유 계정을 확인할 수 없으므로 자동으로 가져오거나 삭제하지 않는다. 새싹 계정도 새로운 전용 범위에서 기본 시연 데이터를 시작한다.
- 기존 `cydemo-*`, 예전 커뮤니티 키, 서버 게시글을 읽거나 가져오지 않는다.
- 글·댓글·공감·스크랩·친구 요청·메시지·프로필 수정은 현재 계정 키에만 저장한다.
- 다른 브라우저/사용자에게 실제 전송하거나 공유하지 않는다.
- 커뮤니티의 **내 정보 → 체험 데이터 초기화**는 현재 계정 키와 현재 계정의 전용 첨부파일 저장소만 초기화한다. 다른 계정, 과거 공용 데이터, 청약진단·로그인·관심 공고는 변경하지 않는다.
- 기존 백엔드 커뮤니티 테이블/API와 예전 UI 파일은 삭제하지 않았지만, 기본 프론트에서 서버형 커뮤니티 스크립트를 로드하거나 API를 호출하지 않는다.
- 새싹 계정의 서비스 홈 커뮤니티 미리보기 역시 `seed.js`의 가짜 데이터로 생성한 요약이다.

## 첨부파일과 관리

- 글·댓글·메시지에서 모든 확장자의 파일을 첨부할 수 있다. 항목당 최대 10개, 파일당 50MB이며 브라우저 저장 용량의 제한도 적용된다.
- 원본은 계정별 `cheongyak-community-demo-attachments-v1:user-<서버 사용자 ID>` IndexedDB에 저장한다. 읽기·삭제·초기화도 해당 DB만 사용한다. JSON에는 `demo-attachment-*` ID와 파일명·크기·유형만 저장한다. 실제 업로드 서버로 보내지 않는다.
- 사진·음성·영상은 브라우저가 지원하는 형식에 한해 미리보기·재생한다. HTML·SVG 등은 실행하지 않고 파일 다운로드로 제공한다.
- 저장된 파일은 새로고침 후에도 유지되지만 브라우저 데이터 삭제, 다른 기기, 시크릿 모드에서는 보존을 보장하지 않는다. 실제 개인정보가 있는 파일은 넣지 않는다.
- 메시지의 ×는 대화를 숨길 뿐 메시지·첨부파일을 삭제하지 않는다. ‘숨긴 대화’에서 복원하거나 해당 이웃에게 메시지를 열면 복원된다.
- 친구·추천 이웃·친구 요청·대화·내 활동은 6개 단위로 페이지를 나눈다. 친구·대화는 검색할 수 있다. 친구 해제는 대화를 삭제하지 않는다.
- 내 활동은 현재 페이지 선택/개별 선택 후 일괄 정리한다. ‘내가 쓴 글’은 내 글만, ‘댓글 단 글’은 내 댓글만 삭제하며, ‘내 스크랩’은 즐겨찾기만 해제한다. 삭제된 글·댓글의 미사용 첨부 원본도 정리한다.

## 새로운 이웃 추천

현재는 **외부 AI 모델 없이 로컬에서 계산하는 유사도 추천**이다. 점수는 고정 숫자가 아니다.
내 정보에서 선택한 관심사(60%), 소개·공개 작성글 제목의 코사인 유사도(15%), 같은 지역(15%), 같은 연령대(10%)로 계산한다.
익명 고민 게시판의 글은 비교하지 않는다. 친구·받은 요청·차단한 이웃은 추천에서 제외한다.
실제 청약진단 정보, 자산·소득·주소 등은 읽거나 비교하지 않는다.
향후 실제 AI 임베딩을 붙인다면 이 모듈만 어댑터로 교체하고, 사용자가 공개에 동의한 정보만 전달한다.

## 청약진단과의 후속 연동

현재는 연동하지 않는다. 커뮤니티의 닉네임·지역·연령대는 시연 전용 프로필이다.
내 정보의 이메일/비밀번호 변경 역시 체험이며 실제 로그인 계정을 수정하지 않는다.

추후 연결 시 별도 어댑터로 **닉네임, 현재 지역, 희망 지역, 연령대**만 읽어 초기 선택값에 반영한다.
소득·자산·생년월일·주소·인증정보·서버 사용자 객체 전체를 넘기지 않는다.
현재 지역의 서버 저장 누락, `40대 이상` 연령 구분은 진단 쪽에서 해결한 후 연결한다.
커뮤니티에서 둘러볼 지역을 바꾸어도 진단 답변을 덮어쓰지 않도록 유지한다.
사용자별 저장 범위는 이미 분리되어 있다. 다른 계정의 접근을 허용하더라도 새싹의 초기 글·댓글·친구·대화·스크랩을 복사하지 않고 빈 상태나 해당 계정용 데이터만 사용한다.

## 확인

```powershell
node --test frontend/tests/community-demo*.test.cjs
cd frontend
npm run build
```

실행 후 `/community`, `/community/friends`, `/community/messages`,
`/community/posts/demo-post-1`에서 확인할 수 있다.
커뮤니티 상단 서비스 메뉴로 청약진단·집 찾기·금융생활·내 공간으로 돌아갈 수 있다.
