## 1. 데이터 수집 파이프라인 (`backend/app/data_pipeline/`)

| 모듈 | 출처 | 받아오는 것 |
|---|---|---|
| `applyhome_client.py` | 청약홈 공공데이터 | 공고, 주택형, 경쟁률, 당첨가점, 특별공급 신청현황 (2020년 이후) |
| `competition_client.py` | 청약홈 | 경쟁률/가점 상세 |
| `lh_client.py` | LH(한국토지주택공사) | 공공주택 공고 (API 키 403이면 0건) |
| `sh_client.py` | SH(서울주택도시공사) | 게시판 최근 분양·임대 목록 |
| `finlife_client.py` | 금융감독원 파인 | 주택담보·전세자금 대출 상품과 금리 옵션 |
| `other_ingest.py` | 기타 | 보조 적재 |
| `save_listings.py` | - | 수집 결과를 `listings`/`historical_results`/`loan_products`에 저장 |
| `scheduler.py` | - | 서버가 켜져 있으면 **6시간마다** 전체 재수집 |

못 받아오는 것: 자격 요건 숫자, 단지별 실제 계약금 비율(공고 첨부 PDF), 정책대출(디딤돌 등) 공식 한도 API.
→ 계약금은 분양가의 **10% 가정치**로 대신 계산합니다(REQ-06).

## 2. API 라우트 (`backend/app/api/routes/`)

| 라우트 | 메서드/경로 | 설명 |
|---|---|---|
| `users.py` | `POST /users/`, `GET /users/{id}` | 프로필 저장(같은 이메일이면 갱신)·조회 |
| `listings.py` | `GET /listings/`, `GET /listings/{id}` | 공고 목록(지역·공급유형·페이지)·상세 |
| `recommendations.py` | `GET /recommendations/{user_id}` | 희망 지역 공고를 자격·구간으로 정렬, 최대 50건 |
| `loans.py` | `POST /loans/match` | 부족 자금에 맞는 대출 후보 최대 20건 |
| `chat.py` | `POST /chat/` | 공고 질문 챗봇 (질문 분류 → RAG 검색 → LLM) |
| `commute.py` | `POST /commute/` | 출발지→도착지 대중교통 경로/시간 |

## 3. 서비스 로직 (`backend/app/services/`)

계산 로직은 전부 이 디렉터리에 있고, 프론트는 결과만 받습니다(계산을 프론트에 두지 않는다는 원칙, `260917_3_주제_방향성_정리.md` 11장).

| 모듈 | 역할 |
|---|---|
| `eligibility_filter.py` | 자격 가능/불가능 판정 |
| `probability_estimator.py` | 당첨 확률을 상/중/하 구간으로만 표시 (수치로 말하지 않음, REQ-04) |
| `loan_matcher.py` | 대출 상품 매칭 (소득·지역 아직 미반영) |
| `listing_view.py` | 계약금 10% 가정치, D-day 등 화면용 가공 필드 계산 |
| `listing_rag.py` | 공고 문장 검색. 기본 TF-IDF, `RAG_EMBEDDING_MODEL` 설정 시 KURE-v1 |
| `intent_classifier.py` | 질문을 `term`/`listing`/`api` 세 갈래로 분류 (학습 결과는 [질문분류_학습_결과서.md](./질문분류_학습_결과서.md)) |
| `commute.py` | 카카오(주소→좌표)·ODsay(대중교통 경로) 연동 |

## 4. LLM 챗봇 동작 순서 (`chat.py`)

1. `intent_classifier`로 질문 분류
2. `api` → 추천/대출 API 안내 문구만 반환 (LLM이 자격·금액을 계산하지 않음, REQ-08)
3. `listing`/그 외 → `listing_rag`로 공고 문장 검색 → 근거가 있을 때만 `OPENAI_API_KEY`로 LLM 호출
4. 근거가 없으면 "이 공고에서 확인되지 않았습니다"로 답하고 지어내지 않음

- 원본 수집 데이터는 지우지 않고 누적, 서비스 값은 조회 시 읽기 전용으로 계산
- 모델: `user.py`, `listing.py`, `historical_result.py`, `loan_product.py`
